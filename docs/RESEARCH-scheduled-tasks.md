# 调研：能否自动接入 Claude 桌面定时任务的结果（M12，2026-09-28）

## 结论

**不做自动接入（不读 Claude 的会话文件）。** 用显式的方式：在定时任务 prompt 末尾写一句
`magpie notify` / `magpie ask`（配方见 [INTEGRATIONS.md](INTEGRATIONS.md)）。

## 实测依据

1. **会话找不到**：桌面 app 里的运行 id 是 `local_a8e2bfbd-…`，`~/.claude/projects/**` 下没有任何
   文件名包含它；那次运行时间窗（2026-09-27 21:05–21:16）内，对应项目目录下也没有被写入的会话文件。
   桌面会话 id 和会话文件的对应关系没有公开文档。
2. **认不出是定时任务**：抽查 20 个近期会话文件，用户消息上的 `origin` / `promptSource`
   全是 `{"kind":"human"}` / `sdk`，交互会话和定时任务没有区别字段。
3. **格式是内部实现**：会话文件是 Claude Code 的内部格式，没有稳定性承诺，版本一升就可能静默失效——
   这正是本项目最想避免的「后台失败但以为成功」。
4. **隐私面**：文件监视器需要读机器上所有 Claude 会话全文，只为了找出其中几条。不值得。

## 附带发现并已处理

`Stop` hook 在**每一轮**交互对话结束时都会触发。原映射是 normal（每轮一个 toast），日常使用会很吵。
已改为默认 `info`（只进收件箱，不打扰），需要时 `magpie hook claude-code --stop-severity normal`。
「Claude 在等你」（权限确认、需要输入）仍是 urgent——那才是真正需要人的信号。

## 什么时候重新考虑

Claude 桌面若提供定时任务完成的官方 hook / 事件 / 文件约定，接一个即可，届时新增一个来源适配器，
不影响现有架构（事件只经 API 进入）。
