AI/脚本 → 本机 API/CLI → 收件箱 → 按严重度升级（桌面 toast → 桌宠 → 手机 → 全屏）→ 人回应 → `magpie ask` 交还给 AI。

用户澄清真实需求：「新点子起头应该由你来起……我要知道我要干什么」「计划有点混乱，很多东西会慢慢忘掉」。
样板是孩子的纸质收尾会议卡（`http://10.1.1.13:8097/meeting-sheet.html`）。于是加了：待办/点子池、按时间预算排期、
早报、到点提醒、做完了吗、21:00 收尾、周复盘、MCP 接口；装好、接上 Claude、导入当前挂着的 16 件事。

## 现在装在哪、怎么转

- 程序：`%LOCALAPPDATA%\Magpie`（开机自启）；数据：`%APPDATA%\magpie`；升级前备份：`%APPDATA%\magpie-backup-20260928`。
- Claude：用户级 MCP `magpie`（✔ Connected）；全局 `~/.claude/CLAUDE.md` 有「待办捕获（Magpie）」规则；
  定时任务 `magpie-nightly-review` 每晚 21:10。
- 一天：09:00 早报 → 到点前 5 分钟提醒 → 过时问做完了吗 → 21:00 收尾 → 21:10 Claude 确认明天。
- 重新打包：`npm run release`（仓库根目录）→ 静默装 `target/release/bundle/nsis/Magpie_*_x64-setup.exe /S`。

## 验证是怎么做的

- 170 个测试（core 纯函数穷举 + store 真实文件 + API 集成 + 运行时真实循环），fmt/clippy(pedantic) 零警告。
- 屏幕访问被拒，界面全部用 **WebView2 调试协议** 在真实 app 里点测和截图
  （`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333` + CDP）。
- Telegram 双向对着本地假 Bot API（`tools/mock_telegram.py`）跑通。
- MCP 以子进程跑真实 JSON-RPC 行协议验证。
- 数据迁移先在**真实库副本**（db+wal+shm）上跑过再上线。

## 流程上的失误（已写进 CLAUDE.md 防再犯）

- 两次「测试红着/漏跑 clippy 还提交」（852b50f、8f72068）→ 门禁改成条件提交。
- 两次「脚本式替换没生效却提交，说明写了没发生的改动」（0255ba9）→ `python edit && if 门禁; then commit`，提交前 grep 确认。
- 两次测 CLI 用了旧二进制（`cargo build -p A --example X` 只编 example）。
- Windows 控制台 GBK、Python 字符串里 `\v` `\t` 被当转义，多次把路径写坏 → 写路径用 Write 工具或 `chr(92)`。
