# Magpie 下一步：从「通知器」到「监工型个人助理」

> 2026-09-28 与用户讨论的结论，尚未实施。实施前先把「待定问题」答完。

## 用户原话里的问题

- 和 AI 聊出来的点子、决定、「这步需要你来做」，对话一结束就没了下落，没变成待办。
- 做了安排（比如营销的两个定时任务），过几天就不知道它是干嘛的、什么时候需要自己配合。
- 每个对话各管各的，没人统一看着；事情不算多，但很乱，慢慢就忘了。
- 不只是工作：孩子的学习、家里的事也一样。
- 要的是「监工」：由助理起头、盯进度、追问，而不是等人自己想起来。

## 已经被证明有效的样板：孩子的收尾会议卡

`http://10.1.1.13:8097/meeting-sheet.html`（纸质，每晚 20:40，约 10 分钟）：

1. **对账**：今天三件完成了几件（只数数，不评价）
2. **时间账**：哪件比估计的长、长多少
3. **明日三件**：只写三件，动词开头（「背 20 个词」而不是「英语」）
4. **第一件放哪**：明天先做第几件、几点
5. **熄灯**：计划 21:20，记实际时刻；锚点打勾

周日 20:00 周复盘：锚点做到几天（数卡片不靠回忆）、估时偏差最大的一件、下周调整（本人提议、别人只记不否决）、
课程进度（陶哲轩 / 斯泰恩第几节）、周一三件、是否进入下一阶段（没达标原地多待一周）。
分阶段启用：第 1 周只填熄灯行，第 2 周加明日三件，第 3 周加时间账。

**结论：用户要的，就是给自己也来一张这样的卡，而且是电子的、有人帮着捕获和盯着。**

## 模型

一个念头从冒出来到做完，五步，每步都有人接：

| 步骤 | 做什么 | 谁来 |
|---|---|---|
| 捕获 | 对话里出现「需要你做」「以后做」「这个安排何时需要你」→ 写进同一张清单，带**为什么 / 你要做什么 / 何时 / 来自哪次对话** | AI（通过 Magpie 的 MCP/CLI），不靠人记 |
| 点子池 | 新点子先进池子，不直接变待办（用户确认：**要**） | 自动 |
| 排期 | 每晚收尾会从池子/待办里挑**明日三件**，定第一件几点 | 人拍板，AI 建议 |
| 监工 | 早上提醒今天三件；到点提醒第一件；逾期追问 | Magpie（已有提醒/升级/桌宠/手机） |
| 回顾 | 每晚对账 + 时间账；周日周复盘，统计**自动算**（不用翻纸数） | Magpie 算，人看 |

节奏（用户确认）：**每晚复盘并安排第二天**，不是全天追着跑。

分类粗分：工作（网站 / 营销 / 项目）· 家里 · 孩子。每条带「属于谁」（我 / 孩子 / …）。

数据项（草案）：标题（动词开头）、为什么、我要做什么、来源（对话 / 项目 / 定时任务）、领域、属于谁、
状态（点子 → 已排期 → 完成 / 放弃）、日期、时间、**估时 / 实际用时**（时间账要用）。

## 与现有 Magpie 的关系

保留：收件箱、提醒、升级、桌宠、全屏、手机渠道、`magpie ask`、本机 API/CLI。
新增：待办/点子数据、「今天」首页、收尾会流程（电子卡）、周复盘统计、给 AI 用的 MCP 接口、捕获规则。
Magpie 仍然**不内置大模型**：理解自然语言、拆任务的「大脑」是用户已有的 Claude 订阅（通过 MCP 调 Magpie）。

## 已定（2026-09-28）

- 孩子的卡：**先不动**，先做用户自己的。
- 数据：**先放这台电脑**（现有架构），以后要全家共用再搬 homeserver。
- 数量：**不限条数，按时间容量排**。排不下由 AI 取舍（死线 > 卡住别人的 > 顺手的小事 > 点子池），
  每条被挤掉的写明原因和改排日期；时间账校正估时。要有展示、提醒、跟进。
- 每天可用时间用户未给，先按 **180 分钟**（`[planning] daily_minutes`，可改）。
- 大脑 = 用户的 Claude 订阅：每晚 21:00 定时任务跑收尾会，经 MCP/CLI 读写 Magpie，最后 `magpie ask` 请用户确认明日安排。
